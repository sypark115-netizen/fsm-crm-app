# Domain: Data Center / IDC / DC Migration

## 평가위원의 핵심 걱정
"이전하다가 계정계가 멈추면 누가 책임지나?" — 기능보다 **중단 Risk와 통제력**.

## 반드시 보여야 할 것
- 이전 대상 규모(서버·스토리지·네트워크 장비·랙)와 RFP 수치 일치 여부
- 이전 전략: 단계(비핵심→정보계→계정계 등)와 그 순서의 근거, 단계별 Rollback
- **Cutover 계획**: 계획정지 허용시간 대비 작업시간, Go/No-go 기준과 결정 주체, 리허설 횟수
- 서버 이전 ↔ 회선/대외기관 연계 전환의 Dependency 관리
- 이전 중 DR 공백 대책 (이전 기간에 DR이 유효한가)
- 신규 센터 요건: 전력·냉각·상면·이중화 등급·보안 구역·인증 (주장 시 Evidence)
- 데이터 이관 무결성 검증 방법(건수·체크섬 대사)

## KT 차별화 후보 (가설 — Evidence로 확인)
- 회선·DC·이전을 한 사업자가 책임 → Dependency 단일 통제 (Evidence: 통합 이전 실적)
- 자체 DC 운영 경험 → 센터 운영 지표 (Evidence: 가용성 실적, 금융 고객 입주)
- 전국 네트워크 → 대외기관·영업점 회선 전환 동시 수행

## Red Flags
- "무중단 이전" 단정 (계획정지 필요 여부를 감춤) → `VERIFY`, 질의응답 함정
- 이전 실적이 금융 아닌 일반 기업만 → Evidence `WEAK`
- 단계별 일정과 인력 투입 불일치, 리허설 계획 없음
- 물리 이전(장비 운송)인지 신규 구매+데이터 이관인지 불명확
