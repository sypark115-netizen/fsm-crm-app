# Domain: Enterprise IT / SI / AX / Digital Transformation (차세대, 업무시스템 구축)

## 평가위원의 핵심 걱정
"일정 지연·품질 문제로 오픈이 밀리면? 현업 요구를 제대로 반영하나?"

## 반드시 보여야 할 것
- 현행 문제와 목표(To-Be)의 연결 — 고객 업무 언어로
- 범위·산출물·일정 (WBS 수준의 마일스톤), 오픈 전략(빅뱅/단계)과 근거
- 방법론이 *이번 고객*에 맞게 조정된 부분 (표준 방법론 그림만으로는 부족)
- 품질 관리: 테스트 단계·커버리지·성능 테스트·전환 리허설
- 요구사항 관리: 변경 통제, 현업 참여 구조
- 데이터 전환 계획, 병행 운영
- AX의 경우: 업무 재설계(프로세스 변화)와 변화관리, 측정 가능한 성과

## KT 차별화 후보 (가설)
- 인프라·클라우드·네트워크까지 포함한 일괄 책임 (SI 단독 대비 경계 Risk 감소)
- 유사 금융 차세대·업무시스템 실적 (Evidence 필수)

## Red Flags
- 일정이 RFP 기간과 맞지 않거나 단계별 인력 투입과 불일치
- "애자일" 선언 + 금융 고객의 통제·감사 요구와의 조화 설명 없음
- 핵심 개발 인력이 협력사인데 책임 구조 불명확
