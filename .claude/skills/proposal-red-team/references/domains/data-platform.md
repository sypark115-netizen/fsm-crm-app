# Domain: Data / Data Platform (DW, Data Lake, Lakehouse, MyData, 분석계)

## 평가위원의 핵심 걱정
"데이터를 모아놓기만 하고 못 쓰는 플랫폼이 되지 않을까? 개인(신용)정보는 안전한가?"

## 반드시 보여야 할 것
- 활용 시나리오 → 필요한 데이터 → 아키텍처 순서 (기술 먼저가 아니라 활용 먼저)
- 데이터 거버넌스: 메타데이터·카탈로그, 품질 관리(지표·책임자), 표준화
- 개인(신용)정보: 가명·익명처리, 결합, 접근권한, 이용 목적 통제 — `REGULATORY VERIFY`
- 레거시 이관: 대상 범위, 정합성 검증, 병행 운영 기간
- 성능·확장: 데이터량 증가 가정, 배치/실시간 처리 요건
- 현업 셀프서비스·교육, 정착 지표(사용자 수, 활용 건수)

## KT 차별화 후보 (가설)
- 대규모 데이터 운영 경험(통신 데이터) → 금융 데이터로의 적용 방법이 있을 때만
- 데이터 + AI + 인프라 일괄 수행으로 이관·활용까지 단일 책임

## Red Flags
- 솔루션 로고 나열이 아키텍처를 대신함
- 데이터 품질·거버넌스가 "체계 수립" 한 줄
- 활용 효과가 정성적 ("데이터 기반 의사결정 강화")
