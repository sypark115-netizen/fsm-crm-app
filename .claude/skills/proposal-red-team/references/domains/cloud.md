# Domain: Cloud (Private / Public / Hybrid, 금융 클라우드)

## 평가위원의 핵심 걱정
"클라우드로 가도 감독 요건·보안·비용·종속(Lock-in)에서 문제 없나?"

## 반드시 보여야 할 것
- 대상 업무의 중요도 판단과 그에 맞는 배치(Private/Public/Hybrid) 근거 — `REGULATORY VERIFY`
- CSP 안전성 평가·인증 현황 (주장 시 Evidence + 유효기간 `VERIFY`)
- 데이터 소재(국내 리전), 암호화·키 관리 주체(고객/CSP)
- 아키텍처: 가용영역 이중화, DR 리전, 네트워크 연결(전용회선) 구성
- 운영 모델: 책임공유(RACI), 모니터링·장애 대응, 비용 관리(FinOps)
- Exit 전략: 데이터 반환·이전 가능성, 종속 최소화
- 마이그레이션 방식(Rehost/Replatform/Refactor)과 대상별 선정 기준

## KT 차별화 후보 (가설)
- 금융 전용 클라우드 존 운영 실적, 금융권 입주 고객 (Evidence 필요)
- 클라우드 + 전용회선 + DC를 하나의 SLA로 (책임 경계 단순화)
- 그룹사(KT cloud 등) 활용 시 **책임 주체가 누구인지** 명확할 때만 강점

## Red Flags
- 퍼블릭 클라우드 일반 장점(탄력성·민첩성) 나열 → 금융 고객 문제와 무관
- 비용 절감 % 주장에 산정 근거 없음
- "금융 규제 완벽 준수" 선언만 있고 항목별 대응 없음
- Exit/종료 계획 부재
