# Domain: AI / GenAI / LLM / RAG / AI Agent

## 평가위원의 핵심 걱정
"PoC는 다 된다. 운영에서 틀린 답·정보 유출·책임 문제는 어떻게 하나?"

## 반드시 보여야 할 것
- **Use Case 선정 근거**: 고객 업무의 어떤 병목을, 얼마나(측정 지표) 개선하는가
- 모델 전략: 모델 선택 기준, 내부 배포/외부 API, 교체 가능성(벤더 종속)
- 데이터: 학습·검색 대상 데이터 범위, 개인(신용)정보 처리, 데이터 반출 여부 — `REGULATORY VERIFY`
- RAG 품질: 문서 수집·청킹·권한별 검색(접근통제 연동), 출처 표시
- **정확성·안전성 평가**: 평가셋, 환각률·정답률 측정 방법, 가드레일, Human-in-the-loop
- AI Agent: 실행 권한 범위, 승인 단계, 감사 로그
- 운영(MLOps/LLMOps): 모니터링, 피드백 반영, 모델 업데이트 절차, 비용(GPU/토큰)
- 금융 AI 관련 가이드라인 대응(설명가능성·공정성·책임) — `REGULATORY VERIFY`

## KT 차별화 후보 (가설)
- 자체/협력 모델 + 국내 인프라(GPU, DC) → 데이터 국내 처리 (Evidence: 실제 서비스·고객)
- AICC 등 운영 중인 AI 서비스의 실 운영 지표
- 금융 데이터 거버넌스와 결합한 구축 실적

## Red Flags
- 데모 화면 위주, 측정 지표·평가 방법 없음
- "환각 없음/100% 정확" 주장
- 모델명·버전 나열이 차별화로 제시됨 (누구나 쓸 수 있음 → Replaceability 실패)
- 데이터 보안을 "보안 솔루션 적용" 한 줄로 처리
