# Domain: Security (보안관제, 인프라 보안, 제로트러스트, 개인정보 보호)

## 평가위원의 핵심 걱정
"사고 나면 금융사가 책임진다. 이 보안 체계가 실제 공격과 감사에서 버티나?"

## 반드시 보여야 할 것
- 위협·요건 분석 → 통제 설계 (솔루션 목록이 아니라 통제 목표 기준)
- 개인(신용)정보 보호: 암호화(저장·전송·이전 구간), 키 관리, 마스킹, 접근 로그
- 접근통제: 특권계정 관리, 원격접속, 협력사 인력 통제
- 탐지·대응: 관제 체계(24x7), 침해사고 대응 절차, 보고 체계, 훈련
- 감사 대응: 로그 보존, 증적 관리, 정기 점검
- 인증·평가: 보유 인증(범위·유효기간 `VERIFY`), 취약점 점검 계획

## KT 차별화 후보 (가설)
- 대규모 보안관제 운영 지표·위협 인텔리전스 (Evidence: 탐지·대응 실적)
- 네트워크 레벨 방어(DDoS 등)와 연계한 통합 대응

## Red Flags
- 보안 솔루션 로고 나열
- "완벽한 보안", "해킹 원천 차단"
- 사업 중(이전·구축 기간) 보안 통제가 빠짐 — 사고는 대개 전환 기간에 남
