# Visual Red Team

목적은 예쁜 PPT가 아니다. **평가받아야 할 내용을 평가위원에게 가장 빠르게 보여주는 것.**

## 1. Blind-first 절차 (순서가 핵심)

텍스트를 먼저 읽으면 "읽어서" 판단하게 되어 평가위원의 실제 지각을 흉내 낼 수 없다. 그래서:

1. **이미지만 본다** (`renders/F#/S###.png`). `units/*.md`는 아직 열지 않는다.
2. 기록한다:
   - **3초**: 가장 먼저 눈에 들어오는 요소 1~2개 (위치·크기·색 때문에)
   - **10초**: "이 장표는 ○○에 관한 장표다"라고 이해되는 내용
   - **30초**: 핵심 주장과 Why KT로 이해되는 것
3. 그 다음 `units/*.md`의 GM(작성자 의도)과 비교한다.
4. 10초 이해 ≠ GM 의도 → `MESSAGE DELIVERY FAILURE`. 3초에 보이는 것이 장식·로고·회사명이면 SEE 실패.

여러 장을 한 번에 볼 때는 contact sheet(`*_sheet_##.png`)로 흐름과 반복 패턴(모든 장표가 텍스트 벽 등)을 먼저 보고, 문제 장표만 원본 PNG로 확대한다.

## 2. 결정적 지표로 교차검증 (`<!-- metrics -->` in units)

| 지표 | 경고 기준 (발표본) | 의미 |
|---|---|---|
| `text_chars` | > 400자 | 20분 발표에서 읽히지 않음 |
| `n_text_blocks` | > 8 | 시선이 분산됨 |
| `max_font_pt` vs 본문 | GM과 본문 크기 차 < 1.5배 | 위계가 없음 |
| 본문 최소 폰트 | < 12pt | 평가장 프로젝터에서 안 보임 |
| `picture_area_ratio` | > 0.6 + `text_coverage_low` | 이미지 속 텍스트 — 추출 불가, 이미지로 판독 필요 |

지표는 판단 보조다. 지표가 경고여도 이미지에서 핵심이 잘 보이면 PASS.

`render_report.json`에 폰트 대체 경고가 있으면, 줄바꿈·크기에 대한 지적은 "렌더 환경 한계로 VERIFY"를 붙인다.

## 3. Visual 추천 — 5문항을 반드시 채운다

이미지나 아이콘을 습관적으로 추가하라고 하지 않는다. 추천할 때는:

1. **무엇을** 강조해야 하는가 (원문 요소 인용)
2. 현재 **왜** 잘 보이지 않는가 (위치·크기·밀도·대비)
3. **어떤 Visual 방식**이 적합한가 (아래 카탈로그)
4. **어디에** 배치하는가 (상단 1/3, GM 바로 아래, 좌측 등)
5. 평가위원에게 **어떤 효과**가 있는가 (SEE/UNDERSTAND/BELIEVE/REMEMBER 중)

## 4. Visual 카탈로그 — 언제 쓰나

| 방식 | 적합한 내용 | 부적합 |
|---|---|---|
| Big Number | 핵심 실적·성과 수치 1~2개 (예: "8시간 내 Cutover") | 숫자가 5개 이상 |
| Process Flow | 단계·순서·Cutover 절차 | 병렬 역량 나열 |
| Architecture Diagram | 목표 구성, 이중화·DR 구조 | 조직·일정 |
| Before / After | 현행 문제 → 제안 후 변화 | 신규 구축(비교 대상 없음) |
| Comparison | KT 방식 vs 일반 방식 (경쟁사 실명 비방은 피함) | 근거 없는 우월 주장 |
| 3-Pillar | 전략 3축, Win Theme 3개 | 4개 이상 |
| Reference Map | 유사 실적 다수 (업종·규모 축) | 실적 1건 |
| Roadmap | 단계별 일정·이전 순서 | 단일 시점 |
| Risk Heatmap | 이전 Risk와 대응 | 일반 Risk 목록 |
| Capability + Evidence | 차별화 주장과 근거를 한 쌍으로 | Evidence 없는 역량 |
| KPI Impact | 고객 효과 수치 | 정성 효과만 있을 때(→ Evidence 먼저) |
| Highlight Box / Call-out | 텍스트 장표에서 핵심 1문장 | 모든 문장 |
| Icon | 반복 구조의 범주 구분 | 장식 목적 |

## 5. 흔한 Visual 실패

- **텍스트 벽**: 12줄 이상 불릿, 11pt 이하 — 핵심 1문장을 Highlight Box로 올리고 나머지는 제출본/부록으로.
- **GM과 본문 크기 비슷** — GM이 본문에 묻힘.
- **핵심 숫자가 문장 속**: "…서버 1,180대를 8시간 내…" → Big Number로 분리.
- **차별화 장표가 다른 장표와 똑같은 레이아웃** — 강조가 사라짐.
- **회사 로고·그룹사 로고가 3초 요소** — 고객 문제가 아니라 KT가 먼저 보임.
