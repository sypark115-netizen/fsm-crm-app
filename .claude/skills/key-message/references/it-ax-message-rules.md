# IT · AX 제안 Logic

## IT 제안 (SI, Infra, Network, Data Center, Cloud/MSP, Security)
고객이 실제로 묻는 것: **안정성 · 가용성 · 성능 · 보안 · 전환 리스크 · 운영 · SLA · 확장성 · Architecture · Migration · Integration · TCO · 일정 · 수행 가능성**

- "최적의 Architecture", "안정적인 서비스"는 근거 없는 형용사다. 무엇이 유지되고 무엇이 유연해지는지 쓴다.
  > 최적의 Cloud Architecture를 통해 안정적인 서비스를 제공합니다. → 핵심 업무의 안정성은 유지하고, 변동 수요는 클라우드로 유연하게 대응합니다.
- 전환·이전: **무중단 여부, 대상 규모, 리허설·원복 계획**이 HOW REAL의 핵심. 원문 숫자(서버 수, 회선 수, 리허설 횟수, 원복 시간)를 그대로 끌어올린다.
- 기존 시스템: "그대로 두고 / 단계적으로 / API로 연결" — 전환 리스크를 낮추는 표현은 CIO·IT 담당자에게 강하다.
- SLA·가용률·장애 복구 시간은 숫자 그대로(99.95% ≠ 99.9%). 계약조건·SLA는 절대 바꾸지 않는다.
- Security: 위협 이름 나열보다 "무엇을 막고, 사고 시 몇 분 안에 무엇을 하는지".

## AX 제안 (AI, 생성형 AI, AI Agent, AICC, 업무자동화)
반드시 확인:
1. 어떤 **업무**가 바뀌는가?
2. **AI가 무엇을** 하는가? (찾기·요약·초안·분류·응대·실행)
3. **사람이 무엇을** 하는가? (판단·승인·예외처리·고객 대응)
4. Process가 어떻게 달라지는가? (전/후 단계 수, 재입력 제거)
5. 기존 시스템과 어떻게 연결되는가? (ERP·CRM·그룹웨어, API·Agent Layer)
6. 현업 적용이 가능한가? (파일럿 범위, 데이터 준비, 보안·개인정보)
7. Business Value는 무엇인가? (원문 수치만)
8. 어떻게 확산하는가? (1단계 → 전사)
9. Governance는? (승인 지점, 품질·환각 관리, 책임 소재)

**Human vs AI 역할분담이 AX 메시지의 핵심이다.**
- "End-to-End 자동화", "완전 자동화"는 대기업 고객에게 통제 상실로 읽힌다 → 엔진이 `ax_role_gap`으로 RED 표시.
  > AI Agent를 활용하여 End-to-End 업무 자동화를 구현합니다. → 상담·설계·견적 초안은 AI가 연결하고, 가격과 최종 견적은 담당자가 승인합니다.
- RFP에 "담당자 승인", "사람 검토" 요구가 있으면 Governing에서 반드시 응답한다.

## 업종 Context
엔진의 `industry`(금융·제조·유통·공공·통신·에너지·의료·물류·건설)를 참고해 업종의 언어로 쓴다.
금융: 무중단·규제·감독기관 / 제조: 라인·설비·품질·납기 / 유통: 매장·재고·채널 / 공공: 민원·행정 처리·보안 인증.
업종 사실(규제명 등)은 원문에 있을 때만 쓴다.
