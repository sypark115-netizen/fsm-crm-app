# Examples (Before → After, 판단 근거 포함)

아래 예시는 **관점 예시**다. 문장을 그대로 복사하지 않는다. 고객·사업 자료에 있는 사실로 다시 쓴다.
Learning Loop에 실제 PM의 선택(특히 EDIT)이 쌓이면 그것이 이 파일보다 우선한다.

## 1. AI 상투어 → RED
- 원문: 당사의 차별화된 AI 기술을 기반으로 고객의 디지털 혁신을 가속화합니다.
- 진단: 상투어 5개(당사의·차별화된·기반으로·디지털 혁신·가속화), Swap Test 실패, '차별화'의 근거 없음
- 처리: 근거 없는 '차별화'는 지우고, 제안서 안에 실제로 있는 구조(역할 분담·연결 범위)를 전략 메시지로 끌어올린다.
- 추천: 상담·설계·견적을 하나로 잇고, 반복 작성은 AI가, 가격 판단은 담당자가 맡습니다.

## 2. 좋은 메시지 → GREEN (고치지 않음)
- 원문: 상담부터 견적까지 하나의 Workflow로 연결합니다.
- 진단: 업무 범위가 구체적, 한 문장 한 주장, 상투어 없음
- 처리: KEEP. "더 매끄럽게" 다시 쓰지 않는다.

## 3. Tech → Value
- 원문: 생성형 AI 기반 Intelligent Workplace를 구축합니다.
- 사슬: 생성형 AI → 자료 탐색·요약·초안 → 담당자가 하던 자료 찾기·재입력을 AI가 선처리 → (장표 근거: 견적 1건 평균 3일) → 담당자는 견적 판단에 집중
- 추천: 흩어진 상담·설계 자료는 AI가 찾아 정리하고, 담당자는 견적 판단에 집중합니다.
- Alt (Why 장표용, 장표 본문 수치 사용): 견적 1건에 평균 3일, 같은 정보를 시스템마다 다시 입력하는 구조부터 바꿉니다.

## 4. Automation → Human/AI Role
- 원문: AI Agent를 활용해 견적 업무를 End-to-End 자동화합니다.
- 근거: 같은 장표 표(사람이 하는 일: 누락 확인·사양 확정·가격·할인 승인), RFP SFR-002 "담당자 승인 후 확정"
- 추천: 문의 분석부터 견적 초안까지는 AI Agent가, 가격과 최종 승인은 담당자가 맡습니다.

## 5. Fact Guard — 숫자는 그대로
- 원문: 운영 중인 서버 120대를 체계적인 전환 계획을 통해 무중단으로 이전할 수 있습니다.
- 추천: 운영 중인 서버 120대를 서비스 중단 없이 이전합니다. (120 유지)
- 금지 예: "서버 150대를…" → QA Check `Fact Guard ERROR: 원문·근거에 없는 숫자 생성: 150` → APPLY 차단

## 6. Evidence 부족 → ESCALATE
- 원문: 차별화된 운영 역량을 통해 안정적인 서비스를 제공합니다.
- 처리: 원문 유지. Reason: "추가 검토 가능한 Evidence — 실제 구축 Reference / 적용 업무 수 / SLA·가용률 실적 / 운영 인력 / Architecture 차별성 / PoC 결과"
- 다중 자료에 Reference가 있을 때: Alt A에 "확인 시 사용안"만 둔다 — ERP 운영 3년, 장애 복구 평균 25분·가용률 99.95% 실적으로 운영 안정성을 증명합니다. (Reference.xlsx Row 4, 공개 가능 여부 확인 필요)

## 7. Key가 Governing을 반복
```
BAD   Governing: 당사의 차별화된 AI 기술 …   Key: AI 기반 업무 자동화를 통한 혁신 / 업무 프로세스 고도화 및 디지털 혁신 실현 / 생산성 극대화를 위한 최적의 플랫폼 제공
GOOD  Key: 문의 분석·사양 추천·견적 초안은 AI가 먼저 작성 (How) / 상담→설계→견적 정보를 한 번만 입력 (Why) / 가격·할인·최종 견적은 담당자가 승인 (Difference)
```

## 8. 숫자는 좋은데 과장어 → YELLOW (최소 수정)
- 원문: 견적 작성 시간을 3일에서 4시간으로 단축하여 생산성을 극대화할 수 있습니다.
- 추천: 견적 작성 시간을 3일에서 4시간으로 줄입니다.
- Reason에 "4시간이 목표치인지 PoC 결과인지 출처 확인" — 숫자의 성격을 바꾸지 않는다.

## 9. IT 인프라
- BAD: 최적의 Cloud Architecture를 통해 안정적인 서비스를 제공합니다.
- BETTER: 핵심 업무의 안정성은 유지하고, 변동 수요는 클라우드로 유연하게 대응합니다.
- BAD: 안정적인 데이터센터 이전을 위한 체계적인 수행방안을 제시합니다.
- BETTER: 금융서비스 중단 없이 데이터센터를 이전합니다.

## 10. 기능명 Key → YELLOW
- 원문: 견적서 초안 작성 Agent → 추천: 단가표 기준으로 견적서 초안 작성 (같은 장표 표 근거)
