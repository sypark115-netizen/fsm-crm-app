# Key Message

Key Message는 Governing을 **반복하지 않고 받쳐 준다.**

```
Governing = 핵심 주장
Key 1 = Why   (왜 필요한가 / 고객 Pain)
Key 2 = How   (어떻게 하는가 / 사람·AI·시스템 역할)
Key 3 = Difference / Evidence (무엇이 다르고 무엇으로 증명하는가)
```
모든 장표가 이 3분할일 필요는 없다. 다만 Key 셋이 같은 말을 다른 단어로 반복하면 RED다.

## BAD → GOOD
```
BAD
Governing: AI 기반 업무혁신으로 생산성을 극대화합니다.
Key: AI 기반 업무 자동화 / 업무 프로세스 고도화 / 생산성 극대화

GOOD
Governing: 반복 업무는 AI가 처리하고, 담당자는 판단이 필요한 업무에 집중합니다.
Key: 자료 수집·정리·초안 작성 자동화 / 담당자 검토가 필요한 업무만 선별 / 승인과 예외처리는 사람이 수행
```

## 규칙
- 한 줄 18~40자. 명사형 종결(“~연동”, “~확산”)은 허용한다. 한국 제안서 관행이다.
- **기능 이름만 있는 Key**("견적서 초안 작성 Agent")는 YELLOW → 그 기능이 하는 일로 바꾼다("단가표 기준으로 견적서 초안 작성").
- 같은 장표 표·본문에 있는 사실(숫자·역할 분담)을 Key로 끌어올리는 것은 좋다(Evidence Lift). 출처를 `evidence`에 적는다.
- 작은 글씨의 본문·표·각주는 Key가 아니라 Evidence로 취급한다(엔진이 글자 크기 대역으로 분리).
- Key를 고치면서 Governing과 겹치면(유사도 0.6 이상) 엔진이 "Governing 반복"으로 표시한다.
